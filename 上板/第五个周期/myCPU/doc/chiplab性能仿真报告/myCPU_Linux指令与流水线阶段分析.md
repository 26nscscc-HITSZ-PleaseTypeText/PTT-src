## 0. 数据口径说明（必读）

本报告混用三类数据，含义不同：

| 口径 | 含义 | 来源 |
|------|------|------|
| **动态退休** | 仿真中真正 commit 的指令次数（循环会重复计） | `myCPU PERF` 的 `retire` |
| **动态代理类别** | 用分支训练口 / D$ 访问次数近似类别占比 | PERF（**非**精确 opcode mix） |
| **静态镜像** | `vmlinux` 里出现过多少条某种指令（与执行次数无关） | `objdump -d` |

当前 RTL **没有** commit 级「每条 opcode 执行多少次」直方图，因此动态类别只能代理估计。  
若要精确动态 mix，需在 commit 增加 `futype`/opcode 计数后再跑一轮。

### 2.3 动态 vs 静态为何对不齐

- 静态：内核 ELF 里**写了**多少条；  
- 动态：启动到 shell **跑了**多少次（热函数×循环）。  
- 例如 `ld.w` 静态约 25 万条，动态 D$ load 访问约 **1807 万**，说明访存指令被反复执行。

## 3. 流水线阶段划分（myCPU）

乱序双发射核的阶段与模块对应：

```text
[BPU] → [FTQ] → [IFU + I$] → [IB] → [Decoder×2] → [Rename/RAT]
    → [Dispatch] → [RS: ALU0/ALU1/MEM/MDU] → [FU / LSU+D$]
    → [ROB] → [Commit×2] → (SB 写回 / 训练 BPU)
```

| 阶段编号 | 名称 | 主要硬件 | 每拍能力（设计） |
|----------|------|----------|------------------|
| S0 | 预测 | uBTB / FTB / TAGE / RAS | 基本块预测 |
| S1 | 取指排队 | FTQ | 深 16（有效保留约 14） |
| S2 | 取指+预译码 | IFU + I$ | 最多 4 条/块；I$ 稳态约 1 行/拍 |
| S3 | 指令缓冲 | IB | 深 16；出口 2 条/拍 |
| S4 | 译码 | Decoder×2 | 宽 2 |
| S5 | 重命名/分配 | Rename + RAT + ROB alloc | 宽 2；ROB 有效约 22 项 |
| S6 | 分发 | Dispatch | 宽 2；可同拍双 ALU |
| S7 | 发射/执行 | RS + ALU/LSU/MDU | ALU 乱序；MEM/MDU 顺序 |
| S8 | 访存层级 | LSU、D$、SB、L2/AXI | 单 MSHR（当前） |
| S9 | 提交 | Commit + ROB | 宽 2 |

## 4. 各阶段「流量 / 占用 / 停顿」（动态）

说明：多数探针是 **周期占用或事件次数**，不是「该阶段驻留的指令条数快照」。  
**唯一精确的全路径指令条数是 commit 退休数 1.245×10⁸**；前端会有推测执行，流量 ≥ 退休。

### 4.1 吞吐类（与指令流相关）

| 阶段 | 指标 | 数值 | 解读 |
|------|------|------|------|
| S9 提交 | retire | **124,503,350** | 最终完成的指令条数（100% 基准） |
| S9 提交 | 有提交的周期 | 91,819,464（43.2% 总周期） | 其中双提交 35.6% |
| S9 提交 | 双提交占全周期 | 15.39% | |
| S5 重命名 | alloc 周期 | 83,486,573 | 有 ROB 分配的拍 |
| S5↔S6 | turnover_refill | 64,582,608 | 同拍 vacate+refill（dispatch 解锁） |
| S6 分发 | 任意派发周期 | 84,307,534（**39.7%** 总周期） | 约 **60%** 周期派发为 0 |
| S6 分发 | 双发率 | **76.55%**（相对有派发拍） | 忙时很勤；空转不进分母 |
| S6 分发 | 双 ALU 拍 | 27,613,129 | |
| S0/S2 | I$ cached access | 69,444,232 | 行访问，不是指令条数 |

## 5. Linux 启动时间阶段划分（软件时间线）

内核 `printk` 时间戳（仿真模型时间，非墙钟）：

| 阶段 | 内核时间 | 标志 | 说明 |
|------|----------|------|------|
| P0 固件/串口探活 | ~0 | `abcdefghij` / `uart work!` | 进内核前 |
| P1 早期启动 | 0.000 → ~0.1s | `Linux version` … 内存/IRQ | 建页表、校准 |
| P2 子系统初始化 | ~0.1 → ~2.5s | net/serial/nand/… | 驱动 probe |
| P3 切用户态 | ~4.61s | `Freeing unused` → `Run /init` | 释 initmem，起 init |
| P4 shell | ~4.64s+ | `Processing /etc/profile` → `/ #` | 本仿真在此停仿打 PERF |

**限制：** 现有 PERF 是 **全程累计**，没有按 P0–P4 分段的指令条数。  
若要「每个启动阶段退休了多少条」，需要按 PC/符号或时间戳打点采样。

全程约 **1.245 亿** 条指令覆盖 P0–P4；从日志密度看，大量工作在 P1–P3（内核初始化与驱动），P4 很快停。

## 6. 对性能要求高的部分（优先级）

结合 **指令 mix（访存/分支多）** 与 **停顿剖面**：

### 6.1 第一优先级：访存并行与延迟隐藏（S7–S8）

- 动态约 **1/3** 退休与 D$ 访问相关；MSHR busy **19%**、LSU/D$ 等待合计很高。  
- **要求：** 提高 miss 下的并行度（MSHR/pend）、减少 store 缓冲顶满、让 load 尽量不堵窗口。  
- **预期：** 直接减少空转拍，抬升 IPC（比再提高双发率更有效）。

### 6.2 第二优先级：乱序窗口（S5/S9 ROB）

- ROB 有效 11 对已 **max=满**，full **10%**。前端加速后更明显。  
- **要求：** 窗口能罩住一次 D$ miss 的延迟；否则派发再勤也只能空转。  
- **手段：** 有效 ROB 容量、或缩短 miss 延迟（仍归访存）。

### 6.3 第三优先级：分支预测质量与训练（S0）

- 动态分支 **~21%**；准确率已 92%/96%，但仍有 **201 万** 次误预测。  
- **要求：** 降低冲刷频率；减少 FTB/TAGE update overflow（当前 FTB 仍溢 **37 万**、TAGE **16 万**）。  
- **注意：** 省 BRAM 应评估 **表几何（表项多少）**，不要砍 update Q（小 FIFO，砍了只多丢训练）。

### 6.4 已较充足、边际收益低

| 部分 | 现状 |
|------|------|
| 取指 I$/IFU | 已 1 req/拍级；I$ hit 96% |
| Dispatch 双发 | 有货时 76% 双发 |
| 双 ALU | dual_ALU 拍已显著增加 |
| MDU 宽度 | 静态/动态都很少 |

### 6.5 性能需求对照表（给优化排期用）

| 需求等级 | 子系统 | 当前证据 | 建议动作 |
|----------|--------|----------|----------|
| P0 | D$ MSHR / pend / LSU | 19%+13%+13% 级停顿 | 加并行、减串行 miss |
| P0 | ROB 有效深度 | full 10%，max 顶满 | 评估加深或减 guard（慎） |
| P1 | RS_MEM / SB | 占用高、src stall 17% | 深度/唤醒/store 通路 |
| P1 | BPU 训练 FIFO | overflow 仍大 | TAGE Q 再加深或独立读口 |
| P2 | FTB/TAGE **表大小** | 占 BRAM | 仅下板不够时再缩表并重测准确率 |
| P3 | 再加宽 ALU/前端 | 双发已高 | 暂缓 |

## 7. 小结

1. **指令条数：** Linux→`/ #` 动态退休 **124,503,350** 条。  
2. **类别：** 动态约 **21% 分支、~33% 与 D$ 访存相关、其余多为整数**；静态 `vmlinux` 以 `ld.w`/`addi.w`/`move`/`st.w`/分支为主，乘除极少。  
3. **阶段：** 按 BPU→FTQ→IFU/I$→IB→译码→重命名→分发→RS/FU→LSU/D$→提交 划分；精确「每阶段指令条数」仅提交侧完整，其余用吞吐/占用/停顿刻画。  
4. **性能关键路径：** 不是双发不够，而是 **访存停顿 + ROB 顶满** 制造大量空转拍；优化应优先访存并行与窗口，其次分支训练，最后才考虑缩表省 BRAM。
